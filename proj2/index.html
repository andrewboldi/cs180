Part 1.1 · Convolutions from scratch

Four loops and a pad

Before touching any library, we write a 2D convolution ourselves using only numpy arrays and for loops. For every output pixel, we walk over its (2k + 1) × (2k + 1) neighborhood and add up the image times the kernel. Since the image is indexed as im[i − u][j − v] while the kernel is indexed as [u + k][v + k], the filter gets flipped just like a true convolution should.

Discrete convolution

(f ∗ h)[i,j] = Σᵤ Σᵥ h[u,v] f[i−u, j−v]

Every kernel here is the outer product of two 1D filters Dx and Dy times a prefactor. For example, the 3×3 box filter is three ones times three ones divided by 9, and the 9×9 box filter is nine ones times nine ones divided by 81.

Runtime and boundaries

multiply-adds = W · H · (2k+1)²

The runtime here is W × H × (2k + 1)², so the 9×9 box costs nine times as much as the 3×3 box. The boundaries are handled by zero padding the image by k pixels on every side with np.pad, so the kernel never reads outside the array.

# part1dot1 in main.py (progress bar and file writes left out)
CONVS = {
  "box_filter3x3": {"Dx": [1] * 3, "Dy": [1] * 3, "k": 1, "prefactor": 1 / 9},
  "box_filter9x9": {"Dx": [1] * 9, "Dy": [1] * 9, "k": 4, "prefactor": 1 / 81},
  "finite_difference": {"Dx": [1, 0, -1], "Dy": [1, 0, -1], "k": 1, "prefactor": 1},
}
im = cv2.imread("assets/me.png", cv2.IMREAD_GRAYSCALE).astype(np.float32)
w, h = im.shape

for conv_name, conv in CONVS.items():
  im_out = np.zeros_like(im)
  Dx, Dy, k, prefactor = conv["Dx"], conv["Dy"], conv["k"], conv["prefactor"]
  im = np.pad(im, k, mode="constant", constant_values=0)
  for i in range(k, w + k):
    for j in range(k, h + k):
      for u in range(-k, k + 1, 1):
        for v in range(-k, k + 1, 1):
          im_out[i - k][j - k] += prefactor * im[i - u][j - v] * Dx[u + k] * Dy[v + k]

  # scipy convolve 2d comparison
  im_out = scipy.signal.convolve2d(im, np.einsum("i,j->ij", Dx, Dy))

Comparing with scipy

We compare every result to scipy.signal.convolve2d, run on the same zero padded image with the same kernel. Since scipy defaults to "full" mode and we hand it the already padded image, its outputs come out a little bigger than ours (1539 × 2052 instead of 1535 × 2048 for the 3×3 box). Once we crop off that extra 2-pixel border, the 3×3 results match to within a quarter of a gray level. On my 1535 × 2048 photo, the four-loop version took 15 s for the 3×3 box and 2 min 7 s for the 9×9 box, which lines up with the (2k + 1)² factor: 81 multiply-adds per pixel instead of 9.

Part 1.2 · Finite difference operator

Edges from differences

Now we can use scipy.signal.convolve2d. We convolve the cameraman with the finite difference operators Dx and Dy, which respond to changes in intensity along x and along y. Then we combine the two partial derivatives into the gradient magnitude, which is large wherever there is an edge in any direction.

Finite difference operators

Dx = [1 0 −1], Dy = [1 0 −1]ᵀ

Dx compares each pixel's neighbors on the left and right, and Dy does the same above and below.

Gradient magnitude

‖∇I‖ = √((I∗Dx)² + (I∗Dy)²)

We compute it pixel by pixel from the two derivative images.

Choosing a threshold

I wanted to choose a threshold where all the noise disappears yet keeps all the edges in the foreground. If we allow for the tradeoff of removing background edges to get rid of the noise, that threshold is around >67. However, the instructions for 1.2 and the followup in 1.3 seem to suggest we want to keep all the edges, and if we want to preserve the background edges too, we can only choose a very low (and mostly ineffective) threshold of >11. So the edge image above uses >11: the gradient magnitude is clipped to [11, 225] and normalized instead of being fully binarized (see the note at the end of 1.3).

Part 1.3 · Derivative of Gaussian (DoG) filter

Blur first, then differentiate

The finite difference results above are rather noisy. Luckily, we have a smoothing operator handy: the Gaussian. cv2.getGaussianKernel(18, 3) gives a 1D Gaussian with σ = 3, and its outer product with itself is the 2D Gaussian G. We choose the kernel size to be about ±3σ. Then we repeat the steps from 1.2 on the blurred image.

Gaussian filter

G = g gᵀ, g = getGaussianKernel(18, 3)

18 taps with σ = 3 spans about ±3σ around the center.

One convolution instead of two

(I∗G)∗Dx = I∗(G∗Dx)

Convolution is associative, so we can fold Dx and Dy into the Gaussian once to get the derivative of Gaussian filters, and then convolve the image a single time.

Two convolutions

Blur, then Dx and Dy

The DoG filters

G, G ∗ Dx and G ∗ Dy

Note we resize the kernels to be bigger for visualization purposes, and we normalize them so they are between 0 and 255 rather than having negative values.

One convolution

I ∗ (G ∗ Dx) and I ∗ (G ∗ Dy)

Finite difference · 1.2 DoG · 1.3

What differences do you see?

Gaussian smoothing completely removes the speckles and noise, so much that the thresholding must also be removed to prevent edges from disappearing. Therefore, we moved the clip out compared to 1.2 (just 0–255, as expected) to allow the smoothing to remove the noise without removing the edges.

Same result either way

Blurring first and using the DoG filters give the same images. The code checks this with np.allclose for the x derivative, the y derivative, the gradient magnitude and the edge image, and the saved images from the two routes are identical byte for byte.

Note: the binarization of the gradient image was not done anywhere on this page, in 1.2 or 1.3, to avoid losing edges. TA Andrew Goldberg confirmed this is ok on Ed ↗.

Part 2.1 · Image “sharpening”

Unsharp masking

The unsharp mask filter essentially works by amplifying the high frequencies in an image. We find the low frequencies of the image with a Gaussian filter and subtract them from the original, which leaves only the high frequencies. Then we can amplify the high frequencies in the original image by adding an abundance of them back to it. Since high frequencies tend to be associated with the sharpness of an image, we've sharpened the image!

Unsharp mask

f_sharp = f + α (f − f∗g)

f ∗ g keeps the low frequencies, so f − f ∗ g is what is left: the high frequencies.

As a single convolution

f_sharp = f ∗ ((1+α) e − α g)

e is the unit impulse. Our code uses α = 1 and a Gaussian with σ = 3, which makes the unsharp mask filter 2e − g.

Part 2.2 · Hybrid images

Close up, far away

Hybrid images change depending on how far away you look at them: high frequencies dominate up close, but from far away only the low frequencies survive. So we low-pass one image with a Gaussian, high-pass the other one by subtracting its own Gaussian blur, and add the two together. Before filtering, we click the same two points on both images and the starter code recenters, rescales and rotates them so they line up.

Hybrid image

H = I₁∗G_σ₁ + (I₂ − I₂∗G_σ₂)

Every pair gets its own cutoffs (σ1, σ2) and a flag for which image gets the high-pass filter. All of our pairs use σ = 10 for the first image and σ = 15 for the second, and the sum is normalized.

Part 2.3 · Gaussian and Laplacian stacks

Stacks, not pyramids

A stack is like a pyramid without the downsampling, so every level stays the same size as the original image. To make each Gaussian level, we blur the previous level again, and σ doubles every time, so the stack behaves like a pyramid that halves in size at every level. Each Laplacian level is the difference between two neighboring Gaussian levels, and the last Laplacian level is just the last Gaussian level, so adding up the whole Laplacian stack gives back the original image.

Gaussian stack

G₀ = I, Gᵢ = Gᵢ₋₁ ∗ g_σᵢ, σᵢ = 3 · 0.95 · 2^(i−1)

σ goes 2.85, 5.7, 11.4, … up to 182.4 pixels at the eighth level.

Laplacian stack

Lᵢ = Gᵢ − Gᵢ₊₁, L₇ = G₇, Σ Lᵢ = I

The Laplacian levels have negative values, so every level is normalized to 0–255 for display.

Part 2.4 · Multiresolution blending

The Oraple, and friends

To blend two images, we also build a Gaussian stack of the mask. At every level, the first image's Laplacian level is weighted by 255 − Mi and the second image's by Mi, where Mi is level i of the mask's Gaussian stack. Then we add the two together and sum all of the blended levels back up into the final image.

Mask stack

M₀ = mask, Mᵢ = Mᵢ₋₁ ∗ g_σᵢ

The mask goes through the same σ schedule as the two images.

Blend

B = Σᵢ [ (1 − Mᵢ) Lᴬᵢ + Mᵢ Lᴮᵢ ]

In the code the mask stays in 0–255 instead of 0–1, and the final sum is normalized.

Observations

My observation is that the alignment of the images is a really important thing. In the apple and orange images, we had the tops and bottoms guiding the shape of the objects, which made the transition look seamless everywhere. In the mountains, however, the height of the lake is different in the two images, so it looks unnatural (same with mom/sister). However, the blend from left to right does indeed look really smooth in both.
